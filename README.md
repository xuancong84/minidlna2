# MiniDLNA (ReadyMedia) 2.2.0 — live folder edition

This is the world's best-performance DLNA server that can handle giant media folder (e.g., 20TB), many thousands of files and nested folders within a single folder, giant media files (e.g., 8K VR videos), dynamic changes in folders/files, and fast program start-up.

MiniDLNA is a UPnP-A/V and DLNA media server: it shares video, music and
pictures with players on your network (VLC, Kodi, smart TVs, phones,
consoles). Version 2.2.0 is the Debian `minidlna` 1.3.3 source package with local
patches that let it run without a media database:

| Patch | What it changes |
|---|---|
| `16-live-folder-mode-without-database.patch` | With `db_dir` empty, no database, scanner or inotify watcher. Each folder is read from disk when a client opens it. |
| `17-defaults-run-as-invoking-user.patch` | `root_container=B` by default; empty `user=`/`db_dir=` accepted; per-user log and pid files for unprivileged runs. The package no longer creates a `minidlna` system user. |
| `18-cmdline-options-and-cwd-media-dir.patch` | Every config option can be given as `--option=value`; without `-f` no config file is read and the current directory is served; `wide_links=yes` by default. |
| `21-auto-http-port.patch` | Without a port setting, the first free port from 8200 is used; per-port pid file, UUID and default name, so several instances can run side by side. |
| `22-lazy-metadata-for-live-folders.patch` | Live folders learn durations, resolutions, tags and thumbnails for small folders and played files, and item counts for opened folders, in memory. |
| `23-opus-mka-m4b-png-webp.patch` | Adds `.opus`, `.mka`, `.m4b`, `.png` and `.webp`, and makes the video/audio/image extension lists configurable. |
| `24-dont-stall-browsing-on-probes.patch` | Fixes VLC stalling on "Loading" after a restart: larger listen backlog, folder covers only once known, rate-limited probing waits. |
| `26-transliterated-natural-sort.patch` | Live folders are sorted like Python `natsorted(key=unidecode(t).lower())`; `unidecode_table.c` is generated by `tools/gen-unidecode-table.py`. |

## Two modes

**Live folder mode** (default, `db_dir` empty)
- Nothing is scanned at start-up. When a client opens a folder, minidlna
  reads that one folder and `stat()`s only the page of entries the client
  asked for. A folder with 20,000 entries answers in milliseconds once it
  is in the page cache, and Linux OS does all the file caching.
- Clients see your folder tree. Files are typed by extension, with size and
  date; `.srt`/`.smi` subtitles and `cover.jpg` style art next to the files
  are served.
- Order: folders first, then a natural sort of the names transliterated to
  ASCII: `ep2` before `ep10`, `第2集` before `第10集`, Chinese by its pinyin
  among Latin names (`风骚律师` as "feng sao lu shi"), accents and case
  ignored. The client's requested sort order is not used.
  `sort_transliteration` picks how names become sort keys: `pinyin` (the
  default: Chinese by context-aware pinyin from a 200 KB dictionary, 重庆
  "chong qing", 银行 "yin hang", everything else like `unidecode`), `icu`
  (ICU's transliterator; several times slower, which matters on a Raspberry
  Pi) or `unidecode` (exactly
  like Python's `natsorted(key=unidecode(t).lower())`). Keys are cached, so
  each name is transliterated once per run.
- Details are learned only where they are cheap, and kept in memory:
  - **Small folders** (at most `probe_limit`=30 media files): each file is
    probed for duration, resolution, bitrate, DLNA profile and tags while
    the client waits, for at most `probe_time`=500 ms; anything left is
    finished in the background and shows the next time. Waiting is limited
    to a tenth of the time overall: VLC opens every subfolder of a folder it
    shows, and those bursts must not hold up other requests.
  - **Large folders**: nothing is probed; only the names and the page of
    sizes are read.
  - **Played files**: probed in the background on first play, and a video
    gets a thumbnail (a frame, or its embedded cover). Once probed, its
    exact DLNA profile is sent with the stream, which helps TVs seek.
  - **Opened folders**: remember their number of entries, shown by clients
    the next time the parent folder is listed.
  - Everything is checked against the file's size and modification time
    (a folder's modification time), so changed files are re-probed and
    changed folders recounted. Nothing survives a restart.
- Not available: search, Artist/Album/Genre views, resume bookmarks and
  TiVo. Xbox 360/Windows Media Player rely on search.

**Database mode** (`db_dir=/var/cache/minidlna`)
- The original behaviour: all media is scanned into SQLite on start-up and
  kept up to date with inotify, giving the full feature set.

## Build

Install the build dependencies (Ubuntu/Debian):

```sh
sudo apt install build-essential autoconf automake autopoint gettext pkg-config \
    debhelper dh-autoreconf libavcodec-dev libavformat-dev libavutil-dev \
    libexif-dev libflac-dev libid3tag0-dev libjpeg-dev libogg-dev \
    libsqlite3-dev libvorbis-dev libffmpegthumbnailer-dev
# or, from inside this directory:  sudo apt build-dep ./
```

### Plain binary (for development)

```sh
./autogen.sh
./configure --enable-thumbnail
make
./minidlnad -h
```

### Debian package

Build in a copy so the build artifacts stay out of the source tree:

```sh
mkdir -p ~/build
rsync -a --exclude CLAUDE.md ./ ~/build/minidlna-2.2.0/
cd ~/build/minidlna-2.2.0
dpkg-buildpackage -us -uc -b
ls ../minidlna_*.deb
```

The package version comes from the top entry of `debian/changelog`
(currently `2.2.0-1`, which apt treats as newer than Ubuntu's 1.3.3). For a
new release add an entry there, e.g. `dch -v 2.0.1-1 "..."` (package
`devscripts`), and change `AC_INIT` in `configure.ac` and `MINIDLNA_VERSION`
in `upnpglobalvars.h` to match. Only binary packages (`-b`) can be built:
a source package would need a `minidlna_2.2.0.orig.tar.*` tarball.

The source tree has the quilt patches in `debian/patches/` already applied.
To change upstream files, record the change in a patch:

```sh
export QUILT_PATCHES=debian/patches
quilt new 26-my-change.patch && quilt add file.c   # before editing
# ... edit ...
quilt refresh -p ab --no-timestamps --no-index
```

quilt keeps its state in `.pc/`, which is not in git. In a fresh clone,
rebuild it once before using quilt (building packages doesn't need it):

```sh
for p in $(tac debian/patches/series); do patch -R -p1 -s < debian/patches/$p; done
QUILT_PATCHES=debian/patches quilt push -a
```

`unidecode_table.c` is generated; regenerate it after upgrading Python's
Unidecode (needs `python3-unidecode`; nothing else needs Python):

```sh
tools/gen-unidecode-table.py > unidecode_table.c
```

## Install

```sh
cd ~/build
sudo apt install ./minidlna_2.2.0-1_amd64.deb
sudo apt-mark hold minidlna        # keep apt upgrade from replacing it
```

If you edited `/etc/minidlna.conf` before, dpkg asks whether to keep it;
keeping it is safe, and the shipped version is saved next to it as
`/etc/minidlna.conf.dpkg-dist`. To upgrade later, use the same command
with `--allow-change-held-packages`.

## Run as a systemd service

The service starts at boot, runs as root and reads `/etc/minidlna.conf`
(it always passes `-f /etc/minidlna.conf`).

1. Set what to share in `/etc/minidlna.conf`:
   ```ini
   media_dir=/home/me/Videos           # repeat for more folders
   media_dir=A,/home/me/Music          # A, V or P limits the media type
   friendly_name=Living Room Server    # name shown on clients
   #user=me                            # optional: drop root after start-up
   ```
2. Start it and check it:
   ```sh
   sudo systemctl enable --now minidlna
   sudo systemctl restart minidlna     # after every config change
   systemctl status minidlna
   journalctl -u minidlna -f           # log
   ```
   `http://<this-pc>:8200/status` shows the mode and connected clients.

Extra command line options for the service go in `DAEMON_OPTS` in
`/etc/default/minidlna`, for example `DAEMON_OPTS="-r --port=8300"`.

## Run from the command line

Any user can run `minidlnad` directly. Without `-f` it reads no config file
(not even `/etc/minidlna.conf`): built-in defaults and `--option=value`
arguments apply, and it serves the current directory as you:

```sh
cd ~/Videos
minidlnad                          # runs in the background
minidlnad -d                       # foreground, log on the terminal; Ctrl-C stops it
```

Any config file option can be given as `--option=value` or
`--option value` (`-` and `_` are interchangeable) and overrides the file:

```sh
minidlnad --port=8201 --friendly-name="Bob's films" --media-dir=V,/srv/films
minidlnad --media_dir ~/Music --media_dir ~/Pictures   # several folders
minidlnad --wide_links=no          # hide symlinks that leave the media folders
minidlnad --db_dir="$HOME/.cache/minidlna"   # database mode, full features
minidlnad -f ~/my-minidlna.conf    # read a config file (its media_dir and user apply)
minidlnad -h                       # all options
```

Without a port setting, minidlnad takes the first free port from 8200
upwards (8200 is usually the system service, so a shell run gets 8201, the
next one 8202, ...). A background instance logs to
`~/.local/state/minidlna/minidlna.log` and keeps its pid in
`$XDG_RUNTIME_DIR/minidlna/minidlna-<port>.pid`. Stop one, or all of yours:

```sh
kill "$(cat "$XDG_RUNTIME_DIR/minidlna/minidlna-8201.pid")"
pkill -u "$USER" -x minidlnad
```

### Several servers on one computer

Just start more: each one picks the next free port, and one that isn't on
8200 also gets its own UUID and a name ending in `[<port>]`, so clients list
them as separate servers. The discovery port (UDP 1900) is shared, and
clients find every instance whatever its port:

```sh
cd ~/Videos && minidlnad           # e.g. "laptop: me [8201]"
cd ~/Music  && minidlnad           # e.g. "laptop: me [8202]"
minidlnad --friendly-name="Alice's media" --media-dir=/srv/alice   # own name
```

A port given with `--port`, `-p` or `port=` in a `-f` file is used exactly,
and minidlnad exits if it is busy.

## Configuration defaults

| Option | Default | Notes |
|---|---|---|
| `media_dir` | current directory (command line); `/var/lib/minidlna` (service) | `A,`/`V,`/`P,` prefix limits the media type |
| `db_dir` | empty | empty = live folder mode |
| `user` | empty | empty = keep the user that started minidlnad |
| `root_container` | `B` | folder tree; only matters in database mode |
| `wide_links` | `yes` | follow symlinks that point outside `media_dir` |
| `inotify` | `yes` | database mode only |
| `probe_limit` | `30` | live folders: probe folders with at most this many media files while browsing; `0` = never |
| `probe_time` | `500` | live folders: milliseconds a browse may wait for probing |
| `enable_thumbnail` | `yes` (live folders), `no` (database) | video thumbnails; live folders only make them for played files and small folders |
| `video_extensions` | `mpg/mpeg/avi/divx/xvid/asf/wmv/mp4/m4v/mts/m2ts/m2t/ts/vob/mkv/webm/flv/mov/3gp/rm/rmvb` | `/` or `,` separated, case-insensitive; replaces the list |
| `audio_extensions` | `mp3/flac/fla/flc/wma/asf/m4a/m4b/aac/mp4/m4p/wav/ogg/opus/mka/pcm/3gp/dsf/dff` | extensions without a built-in tag reader are probed with libavformat |
| `image_extensions` | `jpg/jpeg/png/webp` | only JPEG gets resized versions |
| `port` | first free from `8200` | a set port is used exactly; the service sets `8200` |
| `network_interface` | all | interface names, comma separated |

See `man minidlna.conf` and `man minidlnad` for every option.

## Troubleshooting

- **Clients don't see the server.** The phone and this computer must be on
  the same network, and the firewall must allow UDP 1900 and the HTTP port:
  `sudo ufw allow from 192.168.0.0/16 to any port 1900 proto udp` and
  `sudo ufw allow from 192.168.0.0/16 to any port 8200:8299 proto tcp`
  (covers instances that stepped past 8200).
  Wi-Fi "AP isolation" or guest networks block discovery.
- **A folder is empty on the client.** The user minidlna runs as must be
  able to read the folder and every parent directory. Only files whose
  extension is in `video_extensions`, `audio_extensions` or
  `image_extensions` are listed (see below).
- **Two servers show up as one.** Instances with an explicit `--uuid` must
  each use a different one.
